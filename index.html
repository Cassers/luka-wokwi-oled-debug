Antes de empezar

Pines y conexiones, explicado fácil

Un pin es una patita metálica de la placa. Cada una tiene una etiqueta impresa (3V3, GND, 21…) y un trabajo. Conectar es unir con un cable el pin de un aparato con el pin correcto del otro. En nuestro montaje bastan 4 cables entre el ESP32 y la pantalla OLED.

VCC → 3V3 energía · rojo

Le da corriente a la pantalla. El ESP32 trabaja a 3,3 voltios, por eso usamos 3V3. Es como el enchufe.

GND → GND tierra · negro

El camino de regreso de la corriente. Sin él no hay circuito: la energía necesita ir y volver. Los dos aparatos deben compartir GND.

SDA → 21 datos · verde

Por aquí viajan los mensajes: qué letras dibujar y dónde.

SCL → 22 reloj · azul

Marca el ritmo, como un metrónomo: en cada «tic» se lee un trocito del mensaje que va por SDA.

SDA y SCL juntos forman I2C

I2C es una «calle» de dos cables donde pueden vivir varios aparatos. Cada uno tiene su número de casa, la dirección. Nuestra OLED vive en la 0x3C (está en diagram.json). El ESP32 escribe a esa dirección y solo la pantalla responde.

El número del código es la etiqueta

El 21 no es «la patita 21 contando desde arriba»: es el pin que tiene 21 impreso al lado (GPIO 21). Busca la etiqueta, no cuentes.

¿Y el print()?

Los pines TX (enviar) y RX (recibir) van al monitor serie de Wokwi. Por ahí llega a tu pantalla el texto de print("vuelta", contador, …).

Cables y código tienen que decir lo mismo

Así lo dice oled_demo.py. Si el cable está en el 21 pero el código dice otro número, el ESP32 habla por una patita donde no hay nadie escuchando.

python · oled_demo.py
from machine import Pin, I2C
import ssd1306

i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)
display = ssd1306.SSD1306_I2C(128, 64, i2c)
I2C(0, …)
Usa el primer controlador I2C del ESP32.
scl=Pin(22)
El reloj sale por el pin 22, donde está el cable azul.
sda=Pin(21)
Los datos salen por el pin 21, donde está el cable verde.
freq=400000
Velocidad del reloj: 400 000 «tics» por segundo.
128, 64
Tamaño de la pantalla en puntitos (píxeles): 128 de ancho por 64 de alto.

Piensa antes de mirar

Si cambias sda=Pin(21) por Pin(19) sin mover el cable, ¿qué verás?

La pantalla se queda negra: el ESP32 manda los datos por el 19, pero la OLED escucha en el 21. Código y cables ya no coinciden.

¿Qué pasa si quitas solo el cable negro (GND)?

La pantalla no enciende. La corriente entra por VCC pero no tiene por dónde volver: el circuito queda abierto.

Si intercambias los cables SDA y SCL en la placa, ¿funcionará?

No. El ESP32 enviaría el ritmo por el cable de datos y los datos por el del ritmo. Hay que devolver los cables a su sitio o cambiar también el código.

¿Por qué en el breakpoint de la línea 29 ya se ve «vuelta 1»?

Porque la línea 27 llama a mostrar_contador, que termina con show(): en ese momento los datos viajan por SDA y SCL y la pantalla se actualiza.

En Wokwi todo es simulado: puedes equivocarte con los cables sin romper nada. Con una placa real, desconecta la energía antes de mover cables.

Aplicar el ajuste local de GHI 0.2.2

Copiar el repositorio no aplica este parche: modifica un archivo de la extensión instalada en el equipo destino.

  1. Detén la depuración. Localiza la instalación activa de GHI 0.2.2 (en Linux suele estar en ~/.vscode/extensions/ghielectronics.micropython-debugger-0.2.2/), sin reutilizar la ruta del profesor.
  2. Guarda una copia intacta de out/debugSession.js en .tools/ghi-debug/debugSession.original.js. No sobrescribas un backup existente sin revisarlo.
  3. Si ya contiene el bucle de tres intentos, compruébalo y no lo reapliques. Si la versión difiere, revisa primero: nada de sustituciones ciegas.
  4. Dentro de launchUart, tras await this.link.open(port, baud); y this.attachEvents();, sustituye solo la llamada siguiente await this.link.conditions(4 /* Cond.Attached */, 0); por este bloque:
js · out/debugSession.js
        // Wokwi can finish booting after UART has already been reopened.
        // A frame sent too early is lost; retry attachment within a bounded window.
        let uartAttached = false;
        for (let attempt = 1; attempt <= 3; attempt++) {
            try {
                await this.link.conditions(4 /* Cond.Attached */, 0);
                uartAttached = true;
                break;
            }
            catch (err) {
                if (attempt === 3) {
                    throw err;
                }
                this.log(`UART still booting; retrying attachment (${attempt}/3)...`);
                await delay(250);
            }
        }
        if (!uartAttached) {
            throw new Error("UART did not become ready after reboot");
        }
  • El bloque va tras this.attachEvents() y antes de this.link.capabilities(); no cambies otras llamadas de conexión.
  • Hasta tres intentos, 250 ms entre fallos; cada petición conserva el timeout de 5 s de DeviceLink.request.
  • Actualizar o reinstalar la extensión puede pisar el parche. El backup es local y tampoco viene con Git.
  • Ejecuta Developer: Reload Window después de guardar y antes de iniciar la simulación.
Pide confirmaciónVersión, backup, bloque localizado y ventana recargada.
7

Iniciar Wokwi desde su panel

  1. Cierra depuraciones anteriores, conexiones mpremote y cualquier puente iniciado a mano.
  2. En el icono lateral de Wokwi: Select Config File → MicroPython-debug/wokwi.toml.
  3. Pulsa Start Simulation, no Start with Debugger (ese es el flujo GDB).
  4. Mantén el simulador visible y sin pausar: una pestaña oculta puede pausar Wokwi.

Montaje: DevKit C V4 + OLED SSD1306. Qué hace cada cable: pines y conexiones.

  • GND → GND.1
  • VCC → 3V3
  • SDA → 21
  • SCL → 22

La pantalla puede estar negra antes de ejecutar show(); eso no indica una avería.

Pide confirmaciónConfiguración seleccionada y montaje visible.

Lanzar el perfil OLED remoto y esperar el puente

  • Abre MicroPython-debug/oled_demo.py y pon un breakpoint en la línea 29, el print posterior a mostrar_contador.
  • En Ejecutar y depurar, selecciona OLED — depuración REMOTA GHI (no Python del PC) y pulsa el triángulo de ese panel, junto al selector. No uses «Depurar archivo Python» del editor.
  • El perfil lanza solo las tareas: puente con --ensure --recover-stale y validación --check. Espera Puente activo. y la comprobación de PID, PTY y propietario. Deja abierta la terminal de la tarea.
  • No lances otro puente manual ni mpremote: GHI transfiere la demo y el controlador con sync: true.
  • El perfil usa UART a 115200 y .tools/wokwi-ghi-uart; que el enlace exista no demuestra que el puente esté vivo.
  • Un reintento (1/3) puede ser normal durante el arranque; espera el resultado final.
