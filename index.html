Antes de empezar

Pines y conexiones, explicado fácil

Un pin es una patita metálica de la placa. Cada una tiene una etiqueta impresa (3V3, GND, 21…) y un trabajo. Conectar es unir con un cable el pin de un aparato con el pin correcto del otro. En nuestro montaje bastan 4 cables entre el ESP32 y la pantalla OLED.

VCC → 3V3 energía · rojo

Le da corriente a la pantalla. El ESP32 trabaja a 3,3 voltios, por eso usamos 3V3. Es como el enchufe.

GND → GND tierra · negro

El camino de regreso de la corriente. Sin él no hay circuito: la energía necesita ir y volver. Los dos aparatos deben compartir GND.

SDA → 21 datos · verde

Por aquí viajan los mensajes: qué letras dibujar y dónde.

SCL → 22 reloj · azul

Marca el ritmo, como un metrónomo: en cada «tic» se lee un trocito del mensaje que va por SDA.

SDA y SCL juntos forman I2C

I2C es una «calle» de dos cables donde pueden vivir varios aparatos. Cada uno tiene su número de casa, la dirección. Nuestra OLED vive en la 0x3C (está en diagram.json). El ESP32 escribe a esa dirección y solo la pantalla responde.

El número del código es la etiqueta

El 21 no es «la patita 21 contando desde arriba»: es el pin que tiene 21 impreso al lado (GPIO 21). Busca la etiqueta, no cuentes.

¿Y el print()?

Los pines TX (enviar) y RX (recibir) van al monitor serie de Wokwi. Por ahí llega a tu pantalla el texto de print("vuelta", contador, …).

Cables y código tienen que decir lo mismo

Así lo dice oled_demo.py. Si el cable está en el 21 pero el código dice otro número, el ESP32 habla por una patita donde no hay nadie escuchando.

python · oled_demo.py
from machine import Pin, I2C
import ssd1306

i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)
display = ssd1306.SSD1306_I2C(128, 64, i2c)
I2C(0, …)
Usa el primer controlador I2C del ESP32.
scl=Pin(22)
El reloj sale por el pin 22, donde está el cable azul.
sda=Pin(21)
Los datos salen por el pin 21, donde está el cable verde.
freq=400000
Velocidad del reloj: 400 000 «tics» por segundo.
128, 64
Tamaño de la pantalla en puntitos (píxeles): 128 de ancho por 64 de alto.

Piensa antes de mirar

Si cambias sda=Pin(21) por Pin(19) sin mover el cable, ¿qué verás?

La pantalla se queda negra: el ESP32 manda los datos por el 19, pero la OLED escucha en el 21. Código y cables ya no coinciden.

¿Qué pasa si quitas solo el cable negro (GND)?

La pantalla no enciende. La corriente entra por VCC pero no tiene por dónde volver: el circuito queda abierto.

Si intercambias los cables SDA y SCL en la placa, ¿funcionará?

No. El ESP32 enviaría el ritmo por el cable de datos y los datos por el del ritmo. Hay que devolver los cables a su sitio o cambiar también el código.

¿Por qué en el breakpoint de la línea 29 ya se ve «vuelta 1»?

Porque la línea 27 llama a mostrar_contador, que termina con show(): en ese momento los datos viajan por SDA y SCL y la pantalla se actualiza.

En Wokwi todo es simulado: puedes equivocarte con los cables sin romper nada. Con una placa real, desconecta la energía antes de mover cables. ¿Quieres saber qué hacen los otros 34 pines? Mira el mapa de pines al final.

Todo ya está instalado. Este es el recorrido de cada sesión: abrir, encender el simulador, lanzar el programa, pausarlo y mirar qué pasa por dentro.

  1. 1

  2. 2

    Encender el simulador

    1. Haz clic en el icono de Wokwi de la barra lateral.
    2. Select Config File → MicroPython-debug/wokwi.toml.
    3. Pulsa Start Simulation. No uses Start with Debugger.

    Verás el ESP32 y la pantalla. Que esté negra es normal: todavía no se ha dibujado nada. Deja el simulador a la vista; si lo ocultas, Wokwi se puede pausar.

  3. 3

    Lanzar tu programa

    1. Abre el panel Ejecutar y depurar (Ctrl+Shift+D).
    2. En el selector de arriba elige qué correr:

    3. Pulsa el triángulo verde de ese panel. No uses el botón de «ejecutar archivo» del editor.
    4. Se abre una terminal y aparece Puente activo. Déjala abierta: es la conexión con el ESP32 simulado.
    5. Si se detiene en Paused on entry, pulsa F5 para seguir.

    Un mensaje de reintento «(1/3)» al arrancar es normal. Espera el resultado final.

  4. 4

    Pausar con un breakpoint

    Un breakpoint es una señal de «para aquí». Haz clic a la izquierda del número de línea: aparece un punto rojo. Cuando el programa llega a esa línea, se congela antes de ejecutarla.

    Mientras está en pausa puedes mirar tres cosas a la vez:

    Variables
    Cuánto vale cada variable ahora mismo.
    Pila de llamadas
    En qué función estás y quién la llamó.
    Simulador
    Lo que la pantalla muestra hasta ese momento.

    Pon los breakpoints dentro de funciones, como practica(). En líneas sueltas fuera de una función, a veces no se detiene.

  5. 5

    Avanzar paso a paso

    F5
    Continuar hasta el siguiente breakpoint.
    F10
    Ejecutar la línea actual y parar en la siguiente.
    F11
    Entrar dentro de la función de esta línea.
    Shift+F5
    Detener la depuración.

    Terminar la sesión

    1. Detén la depuración con Shift+F5.
    2. Cierra la terminal del puente (icono de papelera de la terminal).
    3. Detén Wokwi.

    El ESP32 simulado no guarda nada al apagarse: tu código vive en practica.py y se vuelve a enviar cada vez que lanzas.

  1. Teoría

    La pantalla es una cuadrícula de puntitos

    La OLED tiene 128 puntitos de ancho y 64 de alto. Cada puntito (píxel) tiene una dirección: x cuenta de izquierda a derecha y y de arriba hacia abajo. El (0, 0) es la esquina de arriba a la izquierda.

    Tres órdenes bastan para empezar:

    fill(0)
    Borra todo: pinta la hoja de negro.
    text("Hola", x, y, 1)
    Escribe empezando en el punto (x, y). El 1 es «encendido».
    show()
    Envía el dibujo a la pantalla. Antes de esto no se ve nada.

    Piensa en una hoja: fill y text dibujan en la hoja; show() la pega en la ventana.

  2. Práctica 1

    Tu nombre en la cripta

    Usa: fill · text · show

    python · practica.py
    def practica(display):
    display.fill(0)
    display.text("Feliz Halloween", 0, 0, 1)
    display.text(___, 0, 20, 1)   # escribe tu nombre
    display.show()
    Pista 1

    El texto va entre comillas, igual que "Feliz Halloween".

    Pista 2

    Si no aparece nada, revisa que show() siga al final.

    Comprueba: arriba «Feliz Halloween» y debajo tu nombre. ¿Qué número cambiarías para bajar tu nombre hasta la última línea?

  3. Concepto nuevo

    Dibujar formas

    Además de letras, la pantalla puede dibujar puntos, líneas y rectángulos. Todos empiezan por la esquina de arriba a la izquierda (x, y).

    pixel(x, y, 1)
    Enciende un solo puntito.
    hline(x, y, largo, 1)
    Línea horizontal de largo puntitos.
    rect(x, y, ancho, alto, 1)
    Rectángulo hueco, solo el borde.
    fill_rect(x, y, ancho, alto, 1)
    Rectángulo relleno.

    Igual que con el texto: se dibuja en la hoja y se ve al llamar a show().

  4. Práctica 2

    Calabaza de cuadrados

    Usa: rect · fill_rect

    python · practica.py
    def practica(display):
    display.fill(0)
    display.rect(44, 20, 40, 36, 1)          # cuerpo: empieza en y = 20
    display.fill_rect(60, 12, 8, ___, 1)   # tallo: empieza en y = 12
    display.show()
    Pista 1

    El hueco es el alto del tallo.

    Pista 2

    El tallo empieza en y = 12 y debe tocar el cuerpo, que empieza en y = 20. ¿Cuántos puntitos hay entre los dos?

    Comprueba: un cuadrado hueco con un tallo encima, sin espacio entre los dos. ¿Qué pasa si el alto es muy grande?

  5. Profundización

    Calcular posiciones: centrar y simetría

    Cada letra mide 8 × 8 puntitos: caben 16 letras por línea (128 ÷ 8) y 8 líneas (64 ÷ 8). Para centrar un texto se resta lo que ocupa del ancho total y se reparte a los dos lados:

    x = (128 − letras × 8) ÷ 2

    Ejemplo: «Hola» tiene 4 letras → (128 − 32) ÷ 2 = 48. Los espacios y signos también cuentan.

    Con las formas pasa igual. El cuerpo de la calabaza empieza en x = 44 y mide 40: ocupa de 44 a 83. El ojo izquierdo empieza en x = 52, o sea 8 puntitos dentro del borde. El derecho debe terminar 8 antes del borde derecho; como mide 6 de ancho, también hay que restar esos 6:

    inicio del ojo derecho = 84 − 8 − 6

  7. Concepto nuevo

    Repetir sin copiar: for

    Cuando algo se repite, no hace falta escribirlo muchas veces. for repite las líneas que tiene debajo con sangría (4 espacios a la derecha).

    python · ejemplo
    for i in range(3):
    display.pixel(i * 10, 0, 1)   # se repite 3 veces

    range(3) le da a i los valores 0, 1 y 2: empieza en 0 y no llega al 3. En cada vuelta i vale distinto, así que i * 10 pone cada punto en otro sitio: x = 0, 10, 20.

    range con inicio, fin y paso, y esperar

    range(1, 4)
    1, 2, 3. Empieza en 1, no llega al 4.

    Variables que van sumando

  13. Profundización

    Dibujar en la hoja o mandar una orden

    Hasta ahora todo se dibujaba en la hoja y se veía con show(). Algunas funciones son distintas: son órdenes directas a la pantalla y actúan al instante, sin show().

    invert(1)
    Cambia negro por blanco en toda la pantalla.
    invert(0)
    La deja como estaba.

    Por eso invertir es instantáneo: no cambia el dibujo de la hoja, cambia cómo la pantalla lo muestra.

Mapa de pines del ESP32

La placa del ejemplo es una ESP32 DevKit C V4 y tiene 38 pines, 19 por lado. Aquí está qué hace cada uno. Los colores dicen si puedes usarlo tranquilo en tus proyectos.

  • EnergíaDan corriente a otros aparatos.
  • TierraEl camino de regreso de la corriente.
  • LibresBuenos para tus proyectos: entrada o salida.
  • Solo entradaLeen, pero no pueden encender nada.
  • Cuidado al arrancarFuncionan, pero influyen en cómo enciende la placa.
  • Conexión con el PCPor aquí viajan print() y el código.
  • No tocarEstán conectados a la memoria interna.

Palabras que vas a ver

GPIO
Pin de uso general: tú decides si lee (entrada) o enciende cosas (salida). El número del código es el número GPIO.
Analógico
Lee voltajes intermedios, no solo encendido o apagado. Los pines analógicos del grupo «ADC2» no leen si usas WiFi.
Táctil
Nota cuando lo tocas con el dedo, sin botón.
PWM
Encender y apagar muy rápido. Sirve para regular el brillo de un LED o mover un servo. Casi todos los pines de salida lo pueden hacer.
I2C, SPI, UART
Formas de hablar con otros aparatos por cables. Nuestra OLED usa I2C.
Pin de arranque
La placa lo mira al encender para decidir cómo arrancar. Por eso hay que tener cuidado con lo que se le conecta.

Todos los pines de datos trabajan a 3,3 V. Con una placa real, nunca les metas 5 V. En Wokwi puedes probar sin miedo: no se rompe nada.

  2. Concepto nuevo · Un cable

    Chip 1 · DHT22, el termómetro embrujado

    El DHT22 mide temperatura y humedad. Usa un solo cable de datos: el ESP32 le pide una medida y el sensor responde por el mismo cable, por turnos.

    • VCC → 3V3
    • GND → GND
    • SDA (datos) → 4

    También lleva la OLED conectada como siempre (21, 22, 3V3 y GND) para mostrar los valores.

    Configurar la comunicación, paso a paso

    1. 1

      Importar el módulo

      MicroPython ya trae el idioma del DHT22: se llama dht.

      python
      import dht
from machine import Pin
    2. 2

      Crear el sensor con su pin

      Solo hay que decirle en qué pin está el cable de datos. Si el cable va al 4, el código dice 4.

      python
      sensor = dht.DHT22(Pin(4))
    3. 3

      Pedir una medida

      measure() hace la conversación por el cable: el ESP32 pregunta y el sensor contesta.

      python
      sensor.measure()
    4. 4

      Leer los valores

      Después de medir, se leen los dos números. Entre medidas hay que esperar al menos 2 segundos.

      python
      temperatura = sensor.temperature()   # grados Celsius
humedad = sensor.humidity()         # porcentaje
    5. 5

      Comprobar

      Pon un breakpoint en mostrar(...) y mira temperatura y humedad en Variables. Mientras corre la simulación, haz clic en el DHT22 de Wokwi: aparecen controles para cambiar la temperatura.

    # Chip 1 · DHT22: el termómetro embrujado.
# Protocolo de UN cable: el sensor y el ESP32 se turnan para hablar por el pin 4.
import time
import dht
from machine import Pin, I2C
import ssd1306


def preparar_pantalla():
    i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)
    return ssd1306.SSD1306_I2C(128, 64, i2c)

    # El DHT22 solo necesita saber en qué pin está su cable de datos.
    return dht.DHT22(Pin(4))

    sensor.measure()  # pide una medida nueva al sensor

    display.text("Termometro", 24, 0, 1)

  4. Profundización · I2C

    Chip 2 · MPU6050, la varita mágica

    El MPU6050 mide inclinación y movimiento. Habla I2C, el mismo idioma que la OLED, así que comparte los mismos dos cables: SDA en el 21 y SCL en el 22. ¿Cómo sabe cada chip que le hablan a él? Por su dirección: la OLED es la 0x3C y el MPU6050 la 0x68.

    Configurar la comunicación, paso a paso

    1. 1

      Crear el bus I2C una sola vez

      Un bus para los dos chips, con los pines del reloj y los datos.

      python
      i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)
    2. 2

      Buscar quién está conectado

      scan() pregunta en todas las direcciones y devuelve las que contestan. Las da en decimal: 60 es 0x3C y 104 es 0x68.

      python
      print(i2c.scan())   # [60, 104]
    3. 3

      Despertar el MPU6050

      Los chips I2C guardan su configuración en registros, cajitas numeradas. El MPU6050 arranca dormido: se despierta escribiendo 0 en su registro 0x6B.

      python
      i2c.writeto_mem(0x68, 0x6B, b"\x00")   # (dirección, registro, dato)
    4. 4

      Leer los datos

      La aceleración está en 6 bytes a partir del registro 0x3B: dos por cada eje X, Y, Z.

      python
      datos = i2c.readfrom_mem(0x68, 0x3B, 6)
    5. 5

      Convertir los bytes en números

      Cada eje viene en dos bytes que se juntan en un número con signo. Dividido entre 16384 da la aceleración en «g» (1 g es la gravedad).

      python
      ax = con_signo(datos[0], datos[1]) / 16384
    6. 6

      Comprobar

      Mira la consola: debe imprimir [60, 104]. Pon un breakpoint en mostrar(...) y mira ax y ay. Para «inclinar» la varita, cambia accelX y accelY en chips/2-mpu6050/diagram.json y vuelve a iniciar la simulación.

    Ver el archivo completo: chips/2-mpu6050/varita.py
    python · varita.py
    # Chip 2 · MPU6050: la varita mágica.
# Protocolo I2C: comparte los cables SDA (21) y SCL (22) con la OLED.
# Cada chip tiene su dirección: OLED = 0x3C (60), MPU6050 = 0x68 (104).
import time
from machine import Pin, I2C
import ssd1306

MPU = 0x68          # dirección del MPU6050 en el bus I2C
REG_ENCENDIDO = 0x6B  # registro PWR_MGMT_1: 0 = despierto
REG_ACELERACION = 0x3B  # aquí empiezan los 6 bytes de aceleración X, Y, Z


def preparar_bus():
    return I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)


def despertar_mpu(i2c):
    # Al encender, el MPU6050 está dormido: se despierta escribiendo 0 en su registro.
    i2c.writeto_mem(MPU, REG_ENCENDIDO, b"\x00")


def con_signo(alto, bajo):
    # Junta dos bytes en un número que puede ser negativo (−32768 a 32767).
    valor = (alto << 8) | bajo
    if valor > 32767:
        valor -= 65536
    return valor


def leer_aceleracion(i2c):
    datos = i2c.readfrom_mem(MPU, REG_ACELERACION, 6)
    ax = con_signo(datos[0], datos[1]) / 16384  # 16384 = 1 g en el rango de ±2 g
    ay = con_signo(datos[2], datos[3]) / 16384
    az = con_signo(datos[4], datos[5]) / 16384
    return ax, ay, az


def mostrar(display, ax, ay):
    display.fill(0)
    display.text("Varita magica", 12, 0, 1)
    x = 60 + int(ax * 50)
    y = 34 + int(ay * 20)
    x = max(0, min(120, x))
    y = max(12, min(56, y))
    display.fill_rect(x, y, 8, 8, 1)  # el fantasma se mueve al inclinar
    display.show()


def main():
    i2c = preparar_bus()
    print("Chips encontrados:", i2c.scan())  # debería mostrar [60, 104]
    display = ssd1306.SSD1306_I2C(128, 64, i2c)
    despertar_mpu(i2c)
    for vuelta in range(100):
        ax, ay, az = leer_aceleracion(i2c)
        mostrar(display, ax, ay)  # breakpoint aquí para ver ax, ay
        time.sleep(0.2)


if __name__ == "__main__":
    main()

  6. Concepto nuevo · SPI

    Chip 3 · MAX7219, la calabaza de LEDs

    El MAX7219 controla una matriz de 8 × 8 LEDs. Habla SPI: un cable de reloj, uno de datos y uno llamado CS que funciona como levantar la mano: mientras está en 0, el chip escucha.

    • VCC → 5V
    • GND → GND
    • DIN → 23
    • CLK → 18
    • CS → 5

    Configurar la comunicación, paso a paso

    1. 1

      Crear el bus SPI

      Se indica el reloj (sck) y los datos de salida (mosi). La velocidad es cuántos bits por segundo se envían.

      python
      spi = SPI(2, baudrate=1000000, sck=Pin(18), mosi=Pin(23))
    2. 2

      Preparar el pin CS

      CS empieza en 1: «no te estoy hablando».

      python
      cs = Pin(5, Pin.OUT, value=1)
    3. 3

      Hablar con el chip

      Cada orden son dos bytes: el número del registro y su valor, siempre entre bajar y subir CS.

      python
      cs.value(0)                          # levantar la mano
spi.write(bytes([registro, valor]))  # enviar la orden
cs.value(1)                          # el chip la guarda
    4. 4

      Encender y configurar

      Al arrancar se le dice cómo trabajar: usar las 8 filas, dibujar punto por punto, el brillo, y encender.

      python
      escribir(spi, cs, 0x0B, 7)   # usar las 8 filas
escribir(spi, cs, 0x09, 0)   # punto por punto
escribir(spi, cs, 0x0A, 3)   # brillo (0 a 15)
escribir(spi, cs, 0x0C, 1)   # encender
    5. 5

      Dibujar

      Las filas son los registros 1 a 8. Cada fila es un número binario: cada 1 es un LED encendido.

      python
      escribir(spi, cs, 1, 0b00011000)   # fila 1: dos LEDs en el centro
    6. 6

      Comprobar

      Pon un breakpoint en dibujar(...) y avanza con F5: la matriz cambia entre calabaza y fantasma. Si el dibujo sale girado o como en un espejo, es por cómo está montada la matriz: prueba "layout": "fc16" en los attrs de la matriz en diagram.json.

    Ver el archivo completo: chips/3-max7219/calabaza_leds.py
    python · calabaza_leds.py
    # Chip 3 · MAX7219: la calabaza de LEDs (matriz de 8 × 8).
# Protocolo SPI: reloj (18), datos (23) y un pin de "te hablo a ti" llamado CS (5).
import time
from machine import Pin, SPI

REG_DECODIFICAR = 0x09  # 0 = dibujamos punto por punto, sin números automáticos
REG_BRILLO = 0x0A       # de 0 (tenue) a 15 (máximo)
REG_FILAS = 0x0B        # cuántas filas usar: 7 = las 8 (de 0 a 7)
REG_ENCENDIDO = 0x0C    # 1 = encendido
REG_PRUEBA = 0x0F       # 1 = enciende todo para probar

CALABAZA = [
    0b00011000,
    0b01111110,
    0b11111111,
    0b10111101,
    0b11111111,
    0b10100101,
    0b11011011,
    0b01111110,
]

FANTASMA = [
    0b00111100,
    0b01111110,
    0b11011011,
    0b11111111,
    0b11111111,
    0b11111111,
    0b11111111,
    0b10101010,
]


def preparar_spi():
    spi = SPI(2, baudrate=1000000, sck=Pin(18), mosi=Pin(23))
    cs = Pin(5, Pin.OUT, value=1)  # CS en 1 = "no te estoy hablando"
    return spi, cs


def escribir(spi, cs, registro, valor):
    cs.value(0)                       # 1. levantar la mano: "te hablo a ti"
    spi.write(bytes([registro, valor]))  # 2. enviar dirección del registro y valor
    cs.value(1)                       # 3. bajar la mano: el chip guarda el dato


def iniciar(spi, cs):
    escribir(spi, cs, REG_PRUEBA, 0)
    escribir(spi, cs, REG_FILAS, 7)
    escribir(spi, cs, REG_DECODIFICAR, 0)
    escribir(spi, cs, REG_BRILLO, 3)
    escribir(spi, cs, REG_ENCENDIDO, 1)


def dibujar(spi, cs, filas):
    for numero in range(8):
        escribir(spi, cs, numero + 1, filas[numero])  # las filas son los registros 1 a 8


def main():
    spi, cs = preparar_spi()
    iniciar(spi, cs)
    for vez in range(6):
        dibujar(spi, cs, CALABAZA)  # breakpoint aquí
        time.sleep(1)
        dibujar(spi, cs, FANTASMA)
        time.sleep(1)
    print("Fin del espectáculo")


if __name__ == "__main__":
    main()

    # Chip 4 · UART: el mensaje secreto.
# Protocolo UART (puerto serie): un cable para enviar (TX, 17) y otro para recibir (RX, 16).
# En este circuito el cable sale del 17 y vuelve a entrar por el 16: el ESP32 se habla a sí mismo.
# Con dos placas reales, el TX de una va al RX de la otra (y comparten GND).
import time
from machine import Pin, I2C, UART
import ssd1306


def preparar_pantalla():
    i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)
    return ssd1306.SSD1306_I2C(128, 64, i2c)


def preparar_uart():
    # UART 2, velocidad 9600 bits por segundo. Los dos lados deben usar la MISMA velocidad.
    return UART(2, baudrate=9600, tx=17, rx=16)


def enviar(uart, texto):
    uart.write(texto)


def recibir(uart):
    time.sleep(0.1)  # dar tiempo a que lleguen las letras
    if uart.any():
        return uart.read().decode()
    return ""


def mostrar(display, enviado, recibido):
    display.fill(0)
    display.text("Mensaje secreto", 4, 0, 1)
    display.text("Envie: " + enviado, 0, 24, 1)
    display.text("Llego: " + recibido, 0, 40, 1)
    display.show()


def main():
    display = preparar_pantalla()
    uart = preparar_uart()
    for palabra in ["BOO", "Dulce", "Truco"]:
        enviar(uart, palabra)
        llegada = recibir(uart)
        mostrar(display, palabra, llegada)  # breakpoint aquí
        time.sleep(1)


if __name__ == "__main__":
    main()

  2. Concepto nuevo · Digital

    Sensor 1 · Botón, el caldero de ingredientes

    Un botón es el sensor más sencillo: pulsado o suelto. Cada vez que lo pulsas, el caldero suma un ingrediente.

    • pata 1 → 13
    • pata 2 → GND

    La OLED va conectada como siempre (21, 22, 3V3 y GND) para mostrar los valores.

    Configurar la lectura, paso a paso

    1. 1

      Preparar el pin como entrada con PULL_UP

      Una resistencia interna deja el pin en 1 mientras nadie pulsa. Al pulsar, el botón lo une con GND y se lee 0. Por eso el botón no necesita cable a 3V3.

      python
      boton = Pin(13, Pin.IN, Pin.PULL_UP)
    2. 2

      Leer

      value() devuelve 1 (suelto) o 0 (pulsado).

      python
      ahora = boton.value()
    3. 3

      Detectar el momento de pulsar

      Si solo miras si está en 0, contarías muchas veces mientras lo mantienes. Hay que comparar con la lectura anterior: estaba en 1 y ahora está en 0.

      python
      if antes == 1 and ahora == 0:
    ingredientes += 1
antes = ahora

    • GND → GND

      Crear el ADC en un pin analógico

      Leer el número

  10. Concepto nuevo · Pulsos

    Sensor 5 · Ultrasonido HC-SR04, el radar de vampiros

    Funciona como un murciélago: lanza un sonido que no oímos, el sonido rebota y vuelve. El sensor pone ECHO en 1 todo el tiempo que tarda el viaje. Cuanto más dura, más lejos está el objeto.

    • VCC → 5V
    • GND → GND
    • TRIG → 32
    • ECHO → 33

    Con una placa real, ECHO da 5 V: necesita un divisor de voltaje antes de llegar al ESP32. En Wokwi no hace falta.

    La OLED va conectada como siempre (21, 22, 3V3 y GND) para mostrar los valores.

    Configurar la lectura, paso a paso

    1. 1

      Preparar los dos pines

      TRIG es una salida (el ESP32 dispara); ECHO, una entrada (el sensor responde).

      python
      trig = Pin(32, Pin.OUT, value=0)
echo = Pin(33, Pin.IN)
    2. 2

      Disparar

      Un pulso de 10 microsegundos en TRIG le dice al sensor «mide».

      python
      trig.value(1)
time.sleep_us(10)
trig.value(0)
    3. 3

      Medir cuánto dura ECHO

      time_pulse_us espera a que ECHO se ponga en 1 y cuenta los microsegundos hasta que vuelve a 0. Si pasan 30 000 µs sin eco, devuelve un número negativo.

      python
      duracion = time_pulse_us(echo, 1, 30000)
    4. 4

      Pasar a centímetros

      El sonido tarda unos 29 µs por centímetro, y hace el camino dos veces (ida y vuelta): 58 µs por cada centímetro de distancia.

      python
      cm = duracion / 58
    Ver el archivo completo: sensores/5-ultrasonido/radar.py

# Señal de PULSOS: la distancia se mide por cuánto dura un pulso en ECHO.
from machine import time_pulse_us
import time
from machine import Pin, I2C
import ssd1306


def preparar_pantalla():
    i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)
    return ssd1306.SSD1306_I2C(128, 64, i2c)


def preparar_radar():
    trig = Pin(32, Pin.OUT, value=0)
    echo = Pin(33, Pin.IN)
    return trig, echo


def medir_cm(trig, echo):
    trig.value(1)       # 1. un disparo de 10 microsegundos
    time.sleep_us(10)
    trig.value(0)
    duracion = time_pulse_us(echo, 1, 30000)  # 2. cuánto dura ECHO en 1
    if duracion < 0:
        return -1        # no volvió el eco
    return duracion / 58  # 3. el sonido va y vuelve: 58 µs por centímetro


def mostrar(display, cm):
    display.fill(0)
    display.text("Radar", 44, 0, 1)
    if cm < 0:
        display.text("Sin eco", 36, 28, 1)
    else:
        display.text("%d cm" % int(cm), 44, 28, 1)
        if cm < 50:
            display.text("Vampiro cerca!", 8, 48, 1)
    display.show()


def main():
    display = preparar_pantalla()
    trig, echo = preparar_radar()
    for vuelta in range(300):
        cm = medir_cm(trig, echo)
        mostrar(display, cm)  # breakpoint aquí
        time.sleep_ms(200)

    Sensor 6 · DS18B20, el termómetro del caldero

    El DS18B20 mide temperatura por un bus 1-Wire: un solo cable de datos donde pueden colgar muchos sensores. Cada uno tiene un número de serie único de fábrica (ROM), así que el ESP32 sabe a cuál le pregunta.

    • VCC → 3V3
    • GND → GND
    • DQ (datos) → 4

    Lleva además una resistencia de 4,7 kΩ entre DQ y 3V3 (resistencia de pull-up). El bus la necesita para volver a 1 cuando nadie habla.

    La OLED va conectada como siempre (21, 22, 3V3 y GND) para mostrar los valores.

    Configurar la lectura, paso a paso

    1. 1

      Crear el bus en su pin

      Primero el bus, luego el «idioma» del DS18B20 encima.

      python
      bus = onewire.OneWire(Pin(4))
sensores = ds18x20.DS18X20(bus)
    2. 2

      Buscar sensores

      scan() devuelve la ROM de cada sensor conectado. Con uno, la lista tiene un elemento.

      python
      roms = sensores.scan()
print(len(roms))   # 1
    3. 3

      Pedir la medida y esperar

      La orden llega a todos los sensores del bus a la vez. Tardan hasta 750 ms.

      python
      sensores.convert_temp()
time.sleep_ms(750)
    4. 4

      Leer a uno en concreto

      Aquí se usa la ROM: «tú, el primero, dime tu temperatura».

      python
      temperatura = sensores.read_temp(roms[0])

    # Sensor 6 · DS18B20: el termómetro del caldero.
# BUS 1-Wire: un solo cable de datos donde pueden colgar varios sensores,
# cada uno con un número de serie único (su ROM).
import onewire
import ds18x20
import time
from machine import Pin, I2C
import ssd1306


def preparar_pantalla():
    i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)
    return ssd1306.SSD1306_I2C(128, 64, i2c)


def preparar_sensores():
    bus = onewire.OneWire(Pin(4))
    sensores = ds18x20.DS18X20(bus)
    roms = sensores.scan()  # lista con el número de serie de cada sensor
    return sensores, roms


def leer(sensores, rom):
    sensores.convert_temp()  # orden: «midan la temperatura»
    time.sleep_ms(750)       # el DS18B20 tarda hasta 750 ms en medir
    return sensores.read_temp(rom)


def mostrar(display, temperatura):
    display.fill(0)
    display.text("Caldero", 36, 0, 1)
    display.text("%.1f C" % temperatura, 40, 28, 1)
    if temperatura >= 100:
        display.text("Hierve!", 36, 48, 1)
    display.show()


def main():
    display = preparar_pantalla()
    sensores, roms = preparar_sensores()
    print("Sensores encontrados:", len(roms))
    for rom in roms:
        print("  ROM:", rom.hex())
    if not roms:
        display.fill(0)
        display.text("Sin sensor", 24, 28, 1)
        display.show()
        return
    for vuelta in range(60):
        temperatura = leer(sensores, roms[0])
        mostrar(display, temperatura)  # breakpoint aquí
